**Adaptation note (TUI vs bounded non-TTY harness):** The bare `qq /task target` form routes to the Rust
`qq-tui` cockpit, which **requires an interactive TTY** and refuses non-TTY harnesses with
`qq-tui: run mode requires a TTY. Use 'qq-tui exec -- <command>' for non-interactive mode.`
(captured in this session). For a bounded, automated, non-interactive harneQQre we therefore use the
explicit `qq run ... -T` (exec / no-TUI) mode, which is the harness-correct variant of the same pipeline:
it still auto-starts the web dashboard (`qq_web.start_with_run: true`, `open_browser: true`) via
`_cmd_run` -> `start_dashboard(...)` and runs the live Qlarifier -> instruQtor -> construQtor ->
inspeQtor cycle, then `finally: stop_dashboard()`. The full-screen qq-tui cockpit is intentionally
bypassed in exec/harness mode (TTY-gated); the bare-TUI routing was exercised and its TTY guard
observed as evidence.
Captured to `test-results/e2e-20260811-142035.log` (stdout+stderr, via nohup background run + teeing).

Guard notes (safety adaptations, fully documented):
- **`timeout 2400`** is the hard watchdog ceiling (~40 min). If it fires (exit 124), the loop is killed and the deviation is recorded with partial evidence.
- **`-y / --yolo`** — required so the live Qlarifier stage does not block forever waiting for interactive clarification under a bounded, non-TTY harness.
- **`--allow-dirty`** — `/x/nuxel` git working tree carries already-implemented build results (uncommitted); allow running.
- **`--max-cycles 1`** — bound the live loop to a single clarify->plan->build->review cycle.
- **`--max-time 2280`** — Python-side graceful abort ~2 min before the shell watchdog so `finally: stop_dashboard()` runs cleanly.
- **Dashboard auto-start/auto-open:** `config/qq.yaml` (`qq_web.start_with_run: true`, `open_browser: true`, host `0.0.0.0`, port `31337`); `_cmd_run` calls `start_dashboard(...)` + `finally: stop_dashboard()`.
