## HARNESS EXECUTION AMENDMENT (correction after initial drafting)

During initial teardown testing it was confirmed that the full `qq-tui run` cockpit does **not** auto-exit when its child finishes unless `--exit-when-done` is supplied, and the `qq` launcher does not forward that flag through to the Rust TUI. Under a bounded, redirected harness this would cause the wrapper to hang in the TUI loop until `timeout 1500` fired (exit 124) even after a real FULLY_DONE — preventing a clean terminal exit.

Therefore the identical live pipeline (`_cmd_run` → `start_dashboard` → `run_qontroller` → Qlarifier→instruQtor→construQtor→inspeQtor → `finally: stop_dashboard`) is executed via the **headless `qq-tui exec`** wrapper, which exercises the qq-tui binary AND the full Python run pipeline and exits cleanly when the run terminates:

```
export TTY=true
timeout 1500 /home/wicked/.local/bin/qq-tui exec -- python3 -m qq run \
    /x/nuxel/finish/nuxel-ultimate-build.md /x/nuxel \
    -y --no-repo --max-cycles 1 --max-time 1440
```
Captured to `test-results/e2e-20260811-140716.log`.

This keeps the run bounded (shell `timeout 1500`, Python `--max-time 1440`), non-interactive (`-y`), operating directly on `/x/nuxel` (`--no-repo`, no git checkout/merge churn on the already-complete dirty tree), single-cycle (`--max-cycles 1`).
